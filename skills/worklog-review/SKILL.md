# /worklog-review スキル

四半期末に、貯めたワークログから**目標管理シートの下書き**を作る。**読み取り専用**（worklog は書き換えない。出力は別ファイル）。

ベースパス: `~/.claude/projects/-Users-you-dev/memory/worklog/`

## 1. 対象四半期の決定

- 引数 `FY2026-Q1` のような指定があればそれを使う。
- 無ければ今日の日付から現 FY 四半期を自動判定（4–6=Q1 / 7–9=Q2 / 10–12=Q3 / 1–3=Q4＝前年度）。

## 2. 読み込み（並行）

- `FY<年度>-Q<n>.md` — 当期ワークログ（主資料）。
- `FY<年度>-Q<n>-goals.md` — 当期の目標／プロセス／達成水準。`status: template` なら「目標未登録」として全体振り返り中心に切り替える。
- `../evaluation-axes.md` — 自分の評価軸（F1〜F5）の定義。利用者が用意する。§3-2 の軸別振り返りに使う。
- 補助（当期内の日付のものだけ・量が多ければ要点のみ）:
  - `../ai-handoff/<当期日付>-*.md`
  - `~/dev/digests/meeting-*.md`（当期分）
  - `~/.claude/board/council/triage-*.json`（当期分・任意）

## 3. 生成（目標別）

各目標 G1/G2… について、ワークログのエントリを集約して以下を書く:

- **達成水準に対する結果**: goals の達成水準に照らして、満たせた／部分的／未達を根拠（エントリの成果）付きで。
- **実際にやったプロセス**: 時系列のハイライト（毎日羅列ではなく節目を）。
- **振り返り**: うまくいった点 / 課題・つまずき / 学び・次に活かすこと。

目標にひも付かない作業（関連目標 `-`）は **「目標外で価値を出した仕事」** セクションにまとめる。

## 3-2. 生成（評価軸別）

`## ⚖️ 評価軸の振り返り` セクションを作り、F1〜F5 それぞれについて書く:

- **改善した根拠**: その軸のタグが付いたワークログエントリを、**日付つきで**引く。エントリの成果・アウトプットを具体物として示す。
- **まだ弱いところ**: 前期の指摘に照らして、今期も残っている課題。

**証拠が無い軸は「今期は証拠なし」と正直に書く。** これは上長への説明材料になるので、創作は最も避けたい失敗（Don't 6）。タグが少ないこと自体が「その軸に取り組めていない」という有効な情報なので、埋めようとしない。

軸の定義と前期の評価原文は `../evaluation-axes.md` を参照。この振り返りをもとに、同ファイルの「軸ごとの進捗」欄を期末に更新するようユーザーへ促す（このスキル自身は書き換えない）。

最後に **全体振り返り**: 今期の総括（量・密度・印象的な意思決定・守備ライン）、次期への申し送り。

## 4. 出力

- `~/dev/digests/goal-sheet-FY<年度>-Q<n>.md` に Markdown で書き出す（新規ファイル＝OK）。
- 同内容をターミナルにも表示し、「これはコピペ用の下書き。事実確認のうえ自分の言葉で仕上げて」と添える。

## 注意

- ワークログに無い成果を**創作しない**（ハルシネーション禁止・Don't 6）。根拠が薄い箇所は「要確認」と明示。
- worklog 本体や goals は書き換えない（読み取り専用）。
