# /worklog スキル

目標管理シート用ワークログ（`memory/worklog/`）を**手動で**補う。日々の自動記録は毎夕の `worklog-rollup.sh` が行うので、このスキルは「自動で拾い切れなかった作業を足す」「四半期の目標を登録する」ための補助。

ベースパス: `~/.claude/projects/-Users-you-dev/memory/worklog/`

## 0. 当期の特定（毎回最初に）

今日の日付から FY 四半期を決める（4月始まり）:
- 4–6月 → Q1（年度=今年）/ 7–9月 → Q2 / 10–12月 → Q3 / 1–3月 → Q4（年度=前年）

対象ファイル: `FY<年度>-Q<n>.md`（ワークログ）, `FY<年度>-Q<n>-goals.md`（目標）。

## モード A: 当日エントリの追記（引数なし、または作業内容の説明）

1. ユーザーに「今日の何の作業を記録する？」を確認（既に説明があればそれを使う）。
2. `FY<年度>-Q<n>-goals.md` を Read し、関連する目標 ID（G1/G2…）を特定（無ければ `-`）。
2-2. `../evaluation-axes.md` を Read し、該当する評価軸 ID（F1〜F5）を特定（無ければ `-`）。
   - **実際にその軸に触れた作業だけ**に付ける。全エントリに機械的に付けない。
   - 判断に迷ったら付けない。期末の振り返りで「証拠」として使うため、水増しすると価値が落ちる。
3. ワークログファイルに**当日ブロックがあれば Edit で追記、無ければ当日ヘッダごと追記**する。
   - 全面 Write は memory-guard がブロックするので**必ず Edit**を使う（append-only）。
   - 書式は `worklog/README.md` のエントリ書式に従う:
     ```markdown
     ## YYYY-MM-DD (曜)

     ### [案件] 案件名
     - **関連目標**: G1
     - **やったこと(プロセス)**: …
     - **観点・判断**: …
     - **評価軸**: F1, F4（無ければ -）
     - **成果・アウトプット**: …
     - **状態**: 進行中 | 完了 | 保留
     - **出典**: 手動(/worklog)
     ```
4. 追記結果を要約して表示。

## モード B: 目標の登録/更新（引数 `goals`）

1. ユーザーから今期の目標管理シートの「目標／プロセス／達成水準」を受け取る（貼ってもらう or 対話で聞く）。
2. `FY<年度>-Q<n>-goals.md` を Read し、`G1/G2…` の ID を振って内容を反映する。
   - テンプレ状態（`status: template`）なら Edit で各 G セクションを埋め、frontmatter を `status: active` に更新。
   - 既に active なら、変更箇所を Edit で部分更新（全面上書きしない）。
3. 登録した目標一覧を表示し、「以後の作業はこの ID にひも付きます」と伝える。

## 注意

- このスキルはメモリを **append/部分編集のみ**（Don't 4）。既存記録の全面上書きはしない。
- 大量の過去分をまとめて埋めたい場合は、ロールアップに任せず、当日ぶんだけ簡潔に。
